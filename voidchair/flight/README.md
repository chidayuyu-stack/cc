# 自动跑图

Voidchair v1.0。配套蓝图为 `voidchair_v1.0.nbt`；导入后在网络备份盘中执行一次“加载 / Load”，恢复 1～13 通道的键位电缆。

在 6 号电脑终端按 Ctrl+T 停止现有飞控，执行：

```text
flight/setup.lua
flight/pilot.lua
```

按提示依次输入两个对角点的世界 X/Z、模拟距离（1～32 区块的整数）和巡航高度 Y。巡航高度不受原版建筑高度限制，可以输入 500 以上，例如 560；程序仍会拒绝无效数值。两个点表示目标区域的边界，X/Z 边长需相等（允许 1 格误差）。坐标可以为负数。设置程序会先检查完整路线，确认有效后才保存任务。

- **Z**：开始新任务。自动开启虚拟力，先垂直到巡航高度，再以最高 340 m/s 飞到中心，从中心向外扫描。
- **X**：立即刹停并暂停。松开移动键时悬停，随后可用原有 W/S/A/D、R/F、Q/E 和挡位键手动飞行。
- **再次 X**：先垂直到巡航高度，再以最高 340 m/s 返回原中断点的 X/Z，然后继续未完成的路段。返回过程中再次暂停会保留原扫描断点。
- 完成后自动悬停。再次按 Z 可开始按当前设置生成的新任务。
- Space 仍是虚拟力总开关；关闭会暂停正在执行的任务。需要继续悬停时，请使用 X。

笔刷按世界 X/Z 上的正方形计算，半径为 `模拟距离 × 16` 格。相邻螺旋圈的间距不超过笔刷直径的 90%；为了完整覆盖外边界，最后一圈的间距可能更小，并留出到点判定的误差余量。路线最后补齐外圈剩余边，不会再整圈重复扫描。扫描直线速度目标为 80 m/s，到转角前按剩余距离减速，转角短暂停留 0.15 秒。自动飞行不使用手动挡位。

`config.lua` 中 `scanSpeed = 80`、`transitSpeed = 340`。终端 `NOW` 和仪表盘 `V` 为飞控读取的实际速度。离线模拟验证了控制目标与速度上限，游戏内实测仍需以这些读数为准。

仪表盘现在通过显示连接器同步刷新四行，每行最多 15 字符：`V` 为实际速度（m/s）、`F` 为虚拟力开关；`Y` 为当前高度、`G` 为挡位；第三行为任务阶段；第四行 `P` 为原路线完成百分比、`H` 为巡航高度、`R` 为区块半径。暂停后手动移动和返回断点不会增加扫描进度。尚未配置任务时，后两行显示 Z/X 提示与版本。

## 断点存档

`flight/mission.txt` 保存输入设置；`flight/survey-progress.0` 和 `.1` 交替保存完整原路线、下一个未完成航点、阶段、转角等待余量和原中断点。默认每 2 秒保存，暂停、阶段切换、路段完成以及正常退出时立即保存。写盘失败会暂停任务，终端显示 `SAVE ERROR`；写盘恢复并成功保存后才能按 X 继续。

电脑重启或重新执行 `flight/pilot.lua` 后，已有任务先刹停悬停，按 X 才继续。恢复直接使用已保存的原路线，修改 `mission.txt` 不会改变进行中的任务。已完成路段不会从头重新执行。

异常断电/进程崩溃只能恢复到最后成功的存档；当前尚未保存的路段可能最多回退约 2 秒，无法保证断电瞬间尚未写盘的位置信息。正常按 X 暂停会立即记录断点。单份存档损坏会读取另一份有效存档，两份都损坏时悬停并报错。

若要明确放弃未完成任务，在终端 Ctrl+T 后删除 **两份** `flight/survey-progress.0`、`flight/survey-progress.1`，再运行设置和飞控。不要在需要续扫时删除这两个文件。

## 离线验证

`tests/run_tests.py` 使用 Python 的 `lupa.lua52` 执行 Lua 5.2 测试，全程使用内存文件系统和模拟刚体，不控制游戏飞行器：

```text
python flight/tests/run_tests.py
```

测试包含不同大小和半径下的覆盖范围、速度上限、爬升顺序、进度单调性、重复暂停、双份存档回退，以及实际 `pilot.lua` 的按键、重启、任务完成和写盘失败流程。
